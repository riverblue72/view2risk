# View2Risk 날짜 단위 검증 계획

## 1. 현재 상태와 목표

기존 결과는 IMPTC historical Test(3일, 236 origins / 120 events)에서 나온 것이다.

| 모델 | 평균 H1–H4 Brier |
|---|---|
| Conditional AFT (보정) | 0.01182 |
| 등속 가정 | 0.01562 |
| DD-MDN | 0.01617 |
| Exit-aware XGBoost M1 (보정) | 0.01635 |

- AFT − EA_M1 paired 차이는 −0.0045이고, recording-cluster 95% CI가 0을 포함하지 않았다.
- 한계: Test가 3일뿐이고 여러 번 재사용됐다. CI에 날짜 간 변동이 반영되지 않았다.

이번 목표는 더 좋은 모델을 찾는 것이 아니다. 다음 두 결론이 날짜가 바뀌어도 일관되는지 확인하는 것이다.

1. Conditional AFT의 우위
2. 각 모델의 확률 보정 상태

## 2. 방향

Exit-aware 분할은 이미 IMPTC 15일을 모두 사용한다(Train 8, Validation 2, Calibration 2, Test 3). 쓰지 않은 날짜는 없으므로, 검증은 두 갈래로 나눈다.

| | A. 날짜 단위 교차검증 | B. 외부 데이터 검증 |
|---|---|---|
| 확인 대상 | 날짜가 바뀌어도 결론이 일관되는지 | 처음 보는 데이터에서도 유지되는지 |
| 데이터 | IMPTC 15일을 돌아가며 Test로 사용 | 새 데이터셋 또는 새로 수집한 데이터 |
| 한계 | 모든 날짜를 이미 열람했으므로 미열람 외부 검증은 아님 | inD는 semantic Exit 정답이 없어 정답 구축이 먼저 필요 |
| 시기 | 지금 바로 가능 | 장기 과제 |

A를 해도 "이 확률을 믿어도 된다"고 말할 수는 없다. 다만 Test 3일이라는 가장 큰 약점이 15일로 바뀌고, 결과가 날짜마다 흔들리는지 확인할 수 있다. 이 문서의 계획과 프롬프트는 A 기준이다.

## 3. 방법

### 3.1 실험 전에 프로토콜 고정

이 Test들은 이미 여러 번 열람한 데이터다. 결과를 본 뒤 기준을 바꾸면 검증의 의미가 사라진다. 가설, 지표, 판정 기준을 문서로 쓰고 해시를 남긴 뒤 실행한다.

### 3.2 이중 분할

- 바깥: 15일을 3일씩 5개 fold로 나눈다. 기존 Test 규모와 같고, 기존 Q 감사의 5-fold 날짜 분할과도 맞는다.
- 안쪽: 나머지 12일을 Train 8 / Validation 2 / Calibration 2로 나눈다. 기존 구조와 같다.

### 3.3 모델별 처리

| 모델 | 처리 |
|---|---|
| 등속 가정 | 적합할 파라미터 없음 |
| Conditional AFT | fold마다 기존 설정으로 재적합 |
| Exit-aware XGBoost M0, M1 | fold마다 기존 하이퍼파라미터 그대로 재학습. 탐색 금지 |
| DD-MDN | 재학습 불가. 공식 체크포인트의 학습 날짜를 먼저 확인 |

DD-MDN 학습 날짜 확인이 중요하다. 체크포인트 이름의 "Full"이 전체 데이터 학습을 뜻한다면, DD-MDN은 모든 날짜에서 학습 데이터로 평가받는 셈이 되고 기존 비교도 다시 봐야 한다. 공개 저장소 문서만으로는 확인할 수 없었다.

### 3.4 가설과 판정 기준

**가설 1: AFT 우위**

mean Brier(conditional_AFT_cal) − mean Brier(EA_M1_cal) < 0

- 유지: 날짜→이벤트 계층 부트스트랩 95% CI 상한 < 0, 그리고 15일 중 10일 이상에서 차이가 음수
- 반대 방향: CI 하한 > 0
- 그 외: 확립되지 않음

**가설 2: 보정**

각 모델·각 H에서 로지스틱 재보정 기울기 95% CI가 1을, 절편 95% CI가 0을 포함한다.

- 모델별로 4개 H 중 몇 개를 통과했는지 보고하고, 하나의 판정으로 뭉치지 않는다.
- ECE는 구간 나누기에 민감하므로 보조 지표로 둔다.

판정 기준의 숫자(10/15일, 부트스트랩 횟수 등)는 예시다. 실행 전에 확정하고 고정한다. 중요한 건 숫자가 아니라 결과를 보기 전에 정한다는 점이다.

### 3.5 불확실성 계산

기존 CI는 녹화 단위라서 날짜 간 변동이 빠져 있었다. 이번에는 다음을 쓴다.

- 날짜 → 이벤트 순서의 계층 부트스트랩
- 날짜별 차이 15개의 forest plot
- 클러스터가 15개뿐이라는 한계를 함께 명시

### 3.6 주의할 점

- **재현부터 확인한다.** 기존 코드로 기존 Test 3일 수치가 그대로 나오지 않으면 교차검증 결과를 기존 결과와 비교할 수 없다.
- **H1 사례 수가 적다.** 3일짜리 fold에서 1초 안에 완료한 사례는 20~30개 수준일 것이다. H1 보정 판정은 CI가 매우 넓게 나올 가능성이 높고, 이는 실패가 아니라 그대로 보고할 결과다.

## 4. 코딩 에이전트용 프롬프트

서버의 비공개 작업 트리에서 코딩 에이전트(Claude Code 등)에게 주는 용도다. `<...>` 부분은 실제 값으로 바꾼다.

````markdown
# 과제: View2Risk 완료확률 예측의 날짜 단위 교차검증 (IMPTC 15일)

## 배경
View2Risk는 보행자가 H=1,2,3,4초 안에 횡단을 완료할 확률을 예측하고, 그 확률의 신뢰도를 검증하는 연구다.
기존 결과(IMPTC historical Test, 3일, 236 origins / 120 events)에서:
- Conditional AFT 평균 H1–H4 Brier 0.01182가 가장 낮았다.
- Exit-aware XGBoost M1(보정) 0.01635, DD-MDN 0.01617, 등속 0.01562.
- AFT − EA_M1 paired 차이 −0.0045, recording-cluster 95% CI가 0을 포함하지 않았다.
- 한계: Test가 3일뿐이고 여러 번 재사용됨. CI에 날짜 간 변동이 반영되지 않음.

이번 목표는 더 좋은 모델을 찾는 것이 아니다.
위 두 결론, (1) AFT 우위와 (2) 보정 상태가 15일 전체를 돌아가며 Test로 썼을 때도 일관되는지 확인하는 것이다.

## 작업 위치
- 작업 트리: <VIEW2RISK_WORKDIR>
- 기존 Exit-aware 코드·설정: <경로>
- 기존 결과·GT·체크포인트·manifest는 읽기 전용이다. 새 결과는 <WORKDIR>/date_cv/ 아래에만 쓴다.

## 0단계: 사전 확인 (실험 전에 보고하고 멈출 것)
1. IMPTC 15개 촬영 날짜 목록과 날짜별 이벤트·origin·recording 수를 표로 만든다.
2. 공식 DD-MDN IMPTC 체크포인트가 어떤 날짜/시퀀스로 학습됐는지 확인한다.
   공식 저장소, 논문, config, split 파일을 근거로 쓰고 출처를 남긴다.
   확인할 수 없으면 "미확인"으로 적는다. 추정하지 않는다.
3. Conditional AFT의 정확한 특징, 학습 코드, 기존 하이퍼파라미터를 찾아 기록한다.
4. 위 결과를 date_cv/00_preflight.md로 저장하고 사용자 확인을 기다린다.

## 1단계: 프로토콜 고정 (실행 전)
date_cv/PROTOCOL.md를 작성하고 SHA256을 date_cv/PROTOCOL.sha256에 저장한다. 이후 수정하지 않는다.
수정이 불가피하면 새 버전 파일을 만들고 이유를 적는다.

### 분할
- 바깥 5-fold: 15일을 3일씩 나눈다.
  배정은 날짜 문자열 정렬 후 고정 seed <정수>로 섞어 정한다. 성능을 보고 바꾸지 않는다.
- 안쪽: 각 fold의 나머지 12일을 Train 8 / Validation 2 / Calibration 2로 나눈다. 규칙을 문서에 적는다.
- 같은 날짜·녹화·이벤트가 두 역할에 걸치지 않음을 assert로 검증한다.

### 데이터 규칙 (기존과 동일하게 유지)
- semantic Exit 최초 통과 GT, 0.12초 확인 규칙, 구간·우측 검열 처리
- 0.4초 grid origin 선택, 이벤트당 최대 8 origins, Exit-aware sampling 정책
- unresolved/returned는 실패(0)로 바꾸지 않는다.
- 특징은 과거 관측만으로 계산한다. future-mutation 검사를 유지한다.

### 모델
- constant_speed: 적합 없음
- conditional_AFT: fold마다 기존 설정으로 재적합
- EA_M0, EA_M1: fold마다 기존 하이퍼파라미터 고정 재학습
  (survival:aft, normal, σ=0.15, max_depth=2, eta=0.03, min_child_weight=10, L2=10, seed=42,
  기존 라운드 수 또는 기존 early-stop 규칙 중 원래 쓰던 것)
  하이퍼파라미터 탐색 금지.
- DD-MDN: 재학습하지 않는다. 0단계에서 학습에 쓰인 것으로 확인된 날짜는 결과에 "in-sample"로 표시하고,
  주 분석은 학습에 쓰이지 않은 날짜만으로 따로 계산한다. 미확인이면 모든 DD-MDN 결과에 "학습 날짜 미확인"을 붙인다.
- 확률 보정: 기존과 같은 log-location/scale 보정을 Calibration 날짜에서만 적합한다. raw와 calibrated를 둘 다 보고한다.

### 지표
- 주 지표: event-weighted Brier (H1–H4 각각, 그리고 동일 가중 평균). 검열 처리는 기존 IPCW 방식과 동일.
- 보정: H별 로지스틱 재보정 기울기·절편과 95% CI. ECE(고정 10 bins)와 reliability diagram은 보조.
- 보조: interval NLL, U95 coverage와 width (기존 정의 그대로)

### 가설과 판정 기준
- 가설 1: mean Brier(conditional_AFT_cal) − mean Brier(EA_M1_cal) < 0
  - "유지": 날짜→이벤트 계층 부트스트랩(2,000회) 95% CI 상한 < 0
    그리고 날짜별 차이가 음수인 날짜 ≥ 10/15
  - "반대 방향": CI 하한 > 0
  - 그 외: "확립되지 않음"
- 가설 2: 각 모델·각 H에서 보정 기울기 95% CI가 1을 포함하고 절편 95% CI가 0을 포함
  - 모델별로 4개 H 중 몇 개를 통과했는지 보고한다. 하나의 통과·실패 판정으로 뭉치지 않는다.
- 부차 비교(EA_M1 vs DD-MDN, vs 등속)는 탐색적 결과로만 표시한다.

## 2단계: 실행
- fold별로 학습 → 보정 → 예측을 수행하고, out-of-fold 예측을 date_cv/oof_predictions.parquet에 저장한다.
  (origin_id, date, recording, event, fold, model, H, p, y, 검열 여부, 가중치)
- 모든 fold, 모든 모델의 결과를 보고한다. 실패한 fold는 이유와 함께 남긴다.

## 3단계: 결과물
1. date_cv/results.md
   - 가설 1, 2 판정 결과를 첫 부분에 적는다.
   - fold별 표와 날짜별 표 (Brier, 차이, n_origins, n_events)
   - 날짜별 AFT − EA_M1 차이의 forest plot (date_cv/fig_forest.png)
   - pooled OOF reliability diagram, H별 (date_cv/fig_reliability_H{1..4}.png)
   - 기존 3일 Test 결과와 나란히 비교한 표
2. date_cv/limitations.md
   - 15일 모두 과거에 열람된 데이터이므로 미열람 외부 검증이 아님
   - 클러스터가 15개뿐임
   - DD-MDN 학습 날짜 문제
   - GT가 규칙 기반 정의라는 점
3. 재현 명령, 환경, 각 결과 파일의 SHA256 (date_cv/REPRODUCE.md)

## 금지 사항
- 결과를 본 뒤 분할, 특징, 하이퍼파라미터, 판정 기준을 바꾸지 않는다.
- 기존 결과, GT, 체크포인트를 수정하지 않는다.
- 유리한 fold나 날짜만 골라 보고하지 않는다.
- "통계적으로 우월", "검증됨" 같은 표현은 판정 기준을 통과한 경우에만 쓴다.
  그 경우에도 "IMPTC 15일 날짜 단위 교차검증 범위에서"라는 범위를 붙인다.

  이 경우 차이의 원인을 찾기 전에는 교차검증을 진행하지 않는다.
- 어떤 fold에서 특정 H의 완료 사례가 10개 미만일 때 (판정 방식 재논의 필요)
````
